## Decisions for the coordinator

1. **PGlite for the SQL tests (H1, M3, H5, M13).** The source's SQL suites need `@electric-sql/pglite` (pinned at 0.5.9 in `d21283a`). That is a new devDependency, which the standing rules forbid. Main's `scripts/test-privacy-db.cjs` already expects PGlite, and main's `npm test` does not run it. The options:
   - (a) allow the pinned devDependency;
   - (b) keep the SQL checks as local-stack scripts outside `npm test`, like `mp-races-real.mjs` and `m13-anon-access.mjs`, and put only the Node and mock tests in `npm test`.
2. **014 brings non-Part-1 behaviour:** L6 (the tie and no-points-no-win rule), L19 (rejoining a lobby), M2's 50-round cap, and small reply changes. The options:
   - (a) port 014 unchanged and list those items;
   - (b) write a reduced new migration. That diverges from the source and from any hosted history.
3. **015 and the A3 review timing fixes are optional for Part-1.** 014 plus `36ebd6c` fixes H1, M3 and H5 on main's existing poll. The lead-in client part of 015 (A3R1) builds on M11's `state-poll.ts`, which is not Part-1. Porting 015 without that client part would show the next question during its lead-in. Recommendation: port 014 and `36ebd6c` only, unless M11 is approved.
4. **H2 across instances.** The source fix shares refreshes only inside one process. A complete fix needs either a QF grace period on refresh-token rotation, or a shared lock (for example a DB row). Both are outside the source fix. Phase 4 can port the per-process fix; the remaining limit must be reported.
5. **Lint `.cjs` override.** It turns `no-require-imports` off for `**/*.cjs` in the config. It is not an `eslint-disable` comment, but it is a rule-off. Confirm that it is acceptable, or accept a larger ESM conversion of four scripts.
6. **M13 sign-up.** Disabling Supabase Auth sign-up on hosted is a dashboard step for the user. Decide whether `supabase/config.toml` should also say `enable_signup = false` locally. It is outside 012, and the source didn't change it.
7. **M1 seeding path.** After the route is deleted, local seeding needs `scripts/seed-lexical.ts`. Don't add, or don't let agents run, an npm script that loads `.env.local`.
8. **H3 residue** (not Part-1): flagged words and unsynced cards stay device-only and are lost when a lapsed session triggers main's wipe.

## Incident (local database only)

To show that 012 works, I piped it into `psql` inside `begin; … rollback;`. But 012 has its own `begin`/`commit`, so it **committed on the local database**.

Recovery:
1. A data-only dump of `public`.
2. `npx supabase db reset --local`, which applied the 16 branch migrations, exit 0.
3. The data restored.

Afterwards I checked the counts: 4,256 words, the V1 test player, 20 cards, 27 reviews, 2 consent receipts and 1 preferences row. The 62 anon grant rows and 32 policies are back, matching the branch's migrations again.

Nothing outside the local stack was touched. The edge-runtime container that `functions serve` started was stopped at the end. No dev server or Chrome was started in this phase.
